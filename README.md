# Teamline

**Рабочее пространство для команд, проектов и задач.** Teamline помогает небольшой команде договориться, что нужно сделать, кто отвечает за работу и на каком этапе находится задача.


**Сайт:** [arcflow-opal.vercel.app](https://arcflow-opal.vercel.app) · [Регистрация](https://arcflow-opal.vercel.app/register)

## Назначение продукта

Teamline объединяет публичную страницу с презентацией продукта и приложение с приватными рабочими пространствами. После регистрации пользователь создаёт команду или присоединяется к существующей по приглашению. Участники ведут общие проекты и задачи: назначают исполнителей, определяют приоритет, редактируют описание и меняют статус.

Например, задача «Исправить поиск» относится к проекту сайта, имеет высокий приоритет и назначена одному из участников. Исполнитель переводит её в «В работе», затем «На проверке» и «Готово». Остальные участники команды видят актуальное состояние.

Это сервис организации работы. Редактора кода, исполнения программ и доступа к репозиториям внутри приложения нет.

## Возможности

- Регистрация по имени, email и паролю; вход и завершение сессии.
- Несколько приватных команд и переключение между ними.
- Приглашение участников по ссылке от владельца команды.
- Проекты и общая база задач внутри каждой команды.
- Создание, редактирование и удаление задач: название, описание, исполнитель, проект, приоритет и метки.
- Статусы Backlog, Todo, In Progress, Review и Done; приоритеты Urgent, High, Medium и Low.
- Представление списком или доской, поиск, фильтры и подробная карточка задачи.
- Командное меню по `Ctrl+K` / `Cmd+K` с клавиатурной навигацией.
- Русский и английский интерфейс, переключатель языка в хедере.
- Адаптивная вёрстка, управление фокусом в диалогах и поддержка reduced motion.

Пользовательские названия, описания и имена сохраняются в исходном виде при переключении языка. Примеры на публичной странице используют отдельные демонстрационные данные и не раскрывают задачи зарегистрированных команд.

## Сценарий работы команды

1. Открыть сайт и зарегистрироваться. Минимальная длина пароля — 12 символов.
2. Создать команду. В ней автоматически появляется проект General.
3. Добавить проекты и задачи, назначить исполнителей и приоритеты.
4. В разделе участников создать приглашение и передать ссылку коллегам.
5. Коллега регистрируется или входит в аккаунт и подтверждает присоединение.

Задачи доступны только участникам соответствующей команды. Публичной ленты задач всех пользователей нет. Участники могут редактировать и удалять задачи своей команды; приглашения создаёт только владелец.

Приглашение действует 24 часа и рассчитано на 20 присоединений. Новая ссылка отменяет предыдущую. Рабочее пространство обновляется каждые четыре секунды, пока вкладка видима. Обновления проверяют версию задачи: устаревшая запись возвращает конфликт, чтобы чужие изменения не были незаметно перезаписаны.

## Архитектура

| Уровень | Технологии и ответственность |
| --- | --- |
| Интерфейс | Vue 3, TypeScript, Vue Router; страницы, состояние сессии и команды |
| Сборка и стили | Vite, Tailwind CSS, собственные CSS-токены, Lucide, VueUse Motion |
| API | Node.js 24; JSON HTTP API, авторизация, валидация и cookie-сессии |
| Локальная база | SQLite в `data/arcflow.sqlite` |
| Облачная база | PostgreSQL в Neon через серверную переменную `DATABASE_URL` |
| Публикация | Статическая сборка интерфейса и Node.js Function на Vercel |

Браузер обращается к `/api` на том же домене. В разработке Vite проксирует запросы к Node-серверу. На Vercel API направляется в `api/index.mjs`, а клиентские маршруты открывают SPA. PostgreSQL сохраняет данные независимо от жизненного цикла функций; локальный SQLite-файл в облачной функции не используется.

Модель данных включает пользователей, сессии, команды, членство, проекты, задачи и приглашения. Задача принадлежит команде и проекту; её исполнитель должен быть участником этой команды. Номера `ARC-1`, `ARC-2` и далее выдаются отдельно внутри каждой команды.

Операции API выполняются в транзакциях. В PostgreSQL соединение закрепляется за запросом через AsyncLocalStorage. Версия задачи проверяется непосредственно в UPDATE; присоединение по приглашению блокирует запись до завершения транзакции.

## Локальный запуск

Требуется Node.js 24.x и npm.

```sh
npm ci
npm run dev
```

Интерфейс: `http://127.0.0.1:5174`; API: `http://127.0.0.1:3001`. Команда запускает оба процесса. Внешняя база для локальной разработки не требуется; SQLite-файл создаётся автоматически и исключён из Git.

При необходимости скопировать `.env.example` в `.env`:

| Переменная | Назначение |
| --- | --- |
| `PORT` | Порт самостоятельного Node-сервера, по умолчанию 3001 |
| `HOST` | Адрес прослушивания, локально 127.0.0.1 |
| `APP_ORIGIN` | Точный адрес интерфейса для проверки Origin и ссылок приглашений |
| `DATA_PATH` | Путь к локальной SQLite-базе |
| `DATABASE_URL` | Серверная строка PostgreSQL; при наличии заменяет SQLite |

Секреты нельзя помещать в переменные с префиксом `VITE_`, исходники или Git. Облачные настройки базы хранятся в Vercel.

## Проверки и production-сборка

```sh
npm test
npm run check
npm run build
npm start
```

Тесты проверяют регистрацию, хеширование паролей, сессии, приватность команд, приглашения, валидацию проектов и исполнителей, общие изменения задач, конфликты версий, выход и сохранение данных после перезапуска. Они используют временные локальные базы.

`npm run build` выполняет строгую проверку TypeScript и собирает интерфейс в `dist/`. `npm start` отдаёт сборку и API через самостоятельный сервер. `npm run preview` предназначен для просмотра собранного интерфейса; API нужно запускать отдельно.

Для самостоятельного размещения с SQLite нужен постоянный диск и резервное копирование базы. Для PostgreSQL используются резервные копии провайдера и отдельные настройки окружений.

## Развёртывание на Vercel

1. Импортировать репозиторий GitHub в проект Vercel.
2. Использовать Node.js 24.x. Сборка и маршрутизация заданы в `vercel.json`.
3. Подключить PostgreSQL и добавить серверную переменную `DATABASE_URL`.
4. Установить `APP_ORIGIN` в точный публичный HTTPS-адрес без завершающего слеша.
5. Опубликовать production deployment и проверить регистрацию, команду и приглашения.

HTTPS включает флаг Secure для сессионной cookie. Для preview-окружения нужны собственные `APP_ORIGIN` и база; production Origin не разрешает изменение данных с чужого домена.

## Безопасность и текущие ограничения

Пароли хранятся как salted scrypt-хеши. Сессионные и пригласительные токены генерируются криптографически и сохраняются как SHA-256-хеши. Сессия использует HttpOnly, SameSite=Lax cookie и действует семь дней. SQL-запросы параметризованы. Сервер проверяет доступ к команде; изменение данных требует правильного Origin и JSON. Тело запроса ограничено 32 КБ.

Ограничение частоты запросов действует в памяти экземпляра сервера; на Vercel это не общий распределённый лимит. Перед широким публичным запуском стоит добавить централизованный rate limit и наблюдение за ошибками.

В текущей версии нет подтверждения email, восстановления пароля, отправки писем, удаления аккаунтов и команд или исключения участников. Внешние интеграции на публичной странице являются частью презентации и не подключены. Roadmap группирует проекты; календарное планирование, конфигурируемые спринты и полноценная история уведомлений пока не реализованы. Синхронизация использует периодические запросы, а не WebSocket.

## Структура проекта

```text
api/index.mjs                 Функция Vercel
server/app.mjs                API, авторизация и бизнес-правила
server/database.mjs           SQLite / PostgreSQL, схема и транзакции
server/app.test.mjs           Интеграционные тесты
server/index.mjs              Самостоятельный сервер
scripts/dev.mjs               Запуск frontend и API
src/views/                    Страницы и маршруты
src/components/landing/       Публичная страница
src/components/workspace/     Список, доска и детали задач
src/components/ui/            Диалоги, язык, брендинг, командное меню
src/composables/              Сессии, рабочее пространство, локализация
src/locales/ru.json           Русские строки
src/assets/                   Стили и дизайн-токены
src/data/                     Демонстрационные данные
vercel.json                   Сборка и маршрутизация Vercel
```

Визуальная композиция основана на колонке Linear App из Figma Community. Проект использует собственный брендинг и тексты; примеры клиентов и интерфейсов на публичной странице иллюстративны.
